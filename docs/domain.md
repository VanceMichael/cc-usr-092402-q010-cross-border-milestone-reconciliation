
# 领域约定

跨境合作里程碑对照台记录双方里程碑版本、跨方映射、依赖、时区日历、交付清单、
签收回执、异议材料与可付款结论。主体使用不含真实身份的引用编号，时间字段采用带
偏移量的 ISO 8601 字符串（形如 `2026-10-01T12:00:00+08:00`，不接受无时区的裸日期），
文件或正文只保存 `sha256:<hex>` 摘要及本地引用。

`contracts/entities.json` 列出稳定的字段约定。无效输入在 HTTP 边界返回结构化错误
`{ "error": { "code", "message" } }`，不能通过修改样例数据绕过校验。SQLite 文件由
`DATABASE_PATH` 决定，开发环境默认 `data/app.sqlite3`。

## 身份与权限边界

请求通过 `x-actor-party`（参与方编号）与 `x-actor-role`（角色）识别身份：

- **本方事实**：里程碑版本、交付清单行、交付事件只能由归属方登记；任何一方都可登记
  指向某版本的签收回执（如境外伙伴签收境内交付物）。更正（撤回）只能作用于本方事实。
- **跨方映射**：创建方自动确认本方，对端再确认一次才生效；单方确认的映射不过门。
- **约定角色确认**：里程碑版本以 `required_roles`（形如 `HOME:lead`）约定确认角色，
  角色齐备才形成可付款结论；只能以本方被约定的角色确认。
- **项目负责人**（`project_owner`）可查看合作全景、差异溯源、审计流，并受理/驳回冲正；
  不替代双方做事实登记。

## 里程碑版本与拆分

- 里程碑按 `(cooperation_ref, side, milestone_code)` 追加版本，`revision` 递增，不覆盖历史。
- 跨方映射连接 A/B 两侧版本，关系为 `equivalent` 或 `split`。
- **拆分（R10）**：一个当前版本可拆为至少两个子版本，子版本权重之和必须为 1；
  父版本若已进入付款（存在未冲正的结算条目），必须先对其结论冲正，服务拒绝直接拆分。
- 依赖只有 `finish_to_start` 一种，登记时做环路检测；被依赖版本满足可付款且未被
  冲正，下游的依赖门才成立。

## 确定性重算规则（规则集 v1）

每次事实变更都触发合作级幂等重算，迭代到依赖状态的不动点。规则：

| 规则 | 含义 |
| --- | --- |
| R1 重复去重 | 同清单行同摘要的交付事件、同版本同回执号的回执只计一次（入口幂等）；编号/摘要不同但实物同一的，可显式 `duplicate_of_*_id` 标注，落库留存但不计入。 |
| R2 撤回更正 | 本方以追加的 `fact_corrections(kind=withdraw)` 撤回事实，立即失效；不能物理删除，也不能撤回他方事实。 |
| R3 部分交付 | 每个未撤回清单行的累计有效交付数量达到 `required_qty` 才算交付完成；缺项或数量不足即部分交付，不过门。 |
| R4 假日调整 | 约定日在签收方日历中若为非工作日（假日优先于周模式，调休上班日优先于假日），顺延到下一个工作日；截止为调整后本地日终，完整跳过轨迹写入结论。 |
| R5 迟到证据 | 证据以 `recorded_at`（入库时刻）为准；结算批次关闭后才入库的证据不参与该批次，只在重放的“迟到清单”与当前视角中体现。 |
| R6 完成时刻 | 完成瞬时取“全部清单达标时刻”与“最新有效签收时刻”的较晚者（签收为准）。 |
| R7 逾期判定 | 完成瞬时晚于 R4 调整后的截止瞬时即为逾期；两侧各自按本方日历与时区计算，可能得出相反结论（这正是对账对象）。 |
| R8 映射门 | 跨方映射须未作废且双方确认。 |
| R9 依赖门 | 全部 `finish_to_start` 被依赖版本的最新结论可付款且未被冲正。 |
| R10 里程碑拆分 | 见上节：权重和为 1，已付款先冲正。 |

## 结论与可付款

- 结论（`conclusions`）是**不可变快照**：输入证据、规则版本、判定轨迹 `details_json`
  与证据基指纹 `basis_hash` 全部内嵌；数据库触发器禁止 UPDATE/DELETE。
- 同一证据基重算返回既有结论（幂等）；证据基变化则产生新结论并以
  `supersedes_conclusion_id` 链接前一版。
- “可付款”是派生状态而非结论字段：`客观门满足（gates_met）+ 约定角色确认齐备
  + 未处于争议冻结 + 该付款位置未被冲正`。`GET .../payable` 给出每一项未满足的原因。

## 争议与冻结

- 异议指向一个里程碑版本或一条映射，可附证据摘要。
- 提出异议即冻结**争议集群**：被指向版本、其跨方映射对端、以及沿依赖边传递的全部
  下游版本；冻结只影响这些金额，无关节点照常满足、照常入批结算。
- 异议 `resolved` 或 `withdrawn` 时释放全部关联冻结。

## 冲正与替代（已进入付款的结论的唯一变更路径）

- 已进入结算的结论不能修改、不能删除。变更必须：
  1. 任一方以 `reason_code` 提出冲正（可附证据摘要）；
  2. 项目负责人受理；受理时以当前证据重算产生**替代结论**，原结算条目标记
     `reversed`，记录净额 `net_amount = 替代金额 − 原金额`；
  3. 项目负责人也可驳回，驳回不影响原结论。
- 替代结论满足条件并经角色确认后，可进入后续批次重新付款。

## 结算批次与重放

- 批次创建时为 `open`，关闭时固化 `rule_version` 与 `cutoff_at`（关闭瞬时），
  按截止时刻重算全部当前版本，把满足可付款且未在已关闭批次中结算的版本纳入条目。
- `GET .../batches/:id/replay` 对每个条目给出三种视角：
  - `snapshot_reproduced`：用结论**内嵌的当时证据与规则**重算，必须复现原指纹与金额；
  - `current_matches`：用**当前库内证据 + 批次截止时刻**汇聚重算（迟到证据被排除），
    验证历史结论仍可由现存数据复现；
  - `live_view`：无截止的当前视角，标注证据基是否已偏离该批次及迟到证据清单。
- 规则集未来升级时，旧批次按其固化的 `rule_version` 处理；当前注册表缺失的旧版本
  返回 `rule_unavailable`，不会用新规则静默改写历史。

## 审计与差异溯源

- 所有写操作追加 `audit_events`（只追加，触发器禁止修改/删除）。
- `GET .../versions/:vid/diff` 并排展示双方版本的约定日（含假日顺延轨迹）、
  完成时刻口径与逾期结论，项目负责人据此回答“差异从何产生”。
